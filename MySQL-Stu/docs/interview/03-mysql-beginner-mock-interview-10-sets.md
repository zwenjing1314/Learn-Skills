## 第 1 组：你怎么理解 MySQL？

### 面试官

你先简单说一下，什么是 MySQL？

### 候选人示范回答

MySQL 是一种关系型数据库管理系统，主要用来存储和管理结构化数据。我们可以通过 SQL 语句对数据进行增删改查，也可以用它来设计数据库和表结构。

### 面试官追问

那你说的“关系型”怎么理解？

### 候选人示范回答

我理解的“关系型”，主要是数据通常按表的形式组织，而且表和表之间可以通过主键、外键这些关系关联起来。比如学生表、课程表、成绩表就可以通过关联字段形成业务关系。

### 回答提醒

- 先给定义
- 再补“关系型”是什么意思
- 最后用一个简单业务例子落地

## 第 2 组：你平时最常用的 SQL 有哪些？

### 面试官

你目前最常用的 SQL 有哪些？

### 候选人示范回答

我目前最常用的是 `SELECT`、`INSERT`、`UPDATE`、`DELETE`，也就是最基础的增删改查。另外像 `WHERE`、`ORDER BY`、`GROUP BY`、`JOIN` 这些查询相关语法我也比较常用。

### 面试官追问

那你觉得里面最容易出问题的是哪一类？

### 候选人示范回答

我觉得是 `UPDATE` 和 `DELETE` 最容易出问题，因为如果没有写好 `WHERE` 条件，可能会直接影响整张表。所以我现在会养成先写 `SELECT` 确认命中范围，再执行修改型 SQL 的习惯。

### 回答提醒

- 先说自己熟悉的范围
- 再主动补风险意识

## 第 3 组：主键和外键你怎么理解？

### 面试官

主键和外键分别是什么？

### 候选人示范回答

主键是用来唯一标识一条记录的字段，要求不能重复也不能为 `NULL`。外键是用来建立表和表之间关系的字段，通常引用另一张表的主键。

### 面试官追问

外键的价值是什么？

### 候选人示范回答

我觉得外键最大的价值是保证关联数据的一致性。比如成绩表里如果用了学生 ID 作为外键，那这个学生 ID 必须在学生表里真实存在，这样可以避免出现无效关联数据。

### 回答提醒

- 主键回答“唯一标识”
- 外键回答“建立关系”
- 追问时强调“一致性”

## 第 4 组：多表查询你一般怎么写？

### 面试官

如果让你写一个多表查询，你一般怎么下手？

### 候选人示范回答

我一般会先明确三个问题：要查的字段分别在哪张表、这些表通过什么字段关联、最后想得到的是明细结果还是统计结果。把这三个问题想清楚后，再去写 `JOIN` 会更稳。

### 面试官追问

为什么很多初学者写多表查询容易乱？

### 候选人示范回答

我觉得主要是因为还没先把表关系想清楚，就直接开始写 SQL。这样很容易出现字段不知道来自哪张表、连接条件写错、结果重复等问题。

### 回答提醒

- 回答要有步骤感
- 主动体现方法论

## 第 5 组：索引你怎么理解？

### 面试官

你怎么理解索引？

### 候选人示范回答

索引可以理解成帮助数据库更快定位数据的一种结构，有点像书的目录。它的主要作用是提高查询效率，尤其是在数据量比较大时更有价值。

### 面试官追问

那为什么索引不是越多越好？

### 候选人示范回答

因为索引虽然能提升查询效率，但也会占用空间，而且插入、更新、删除时还要维护索引，所以索引太多会影响写入性能。我的理解是应该优先加在经常过滤、排序、联表的字段上。

### 回答提醒

- 先说作用
- 再说代价
- 最后说使用原则

## 第 6 组：事务你怎么回答更自然？

### 面试官

事务是什么？你怎么理解？

### 候选人示范回答

事务就是把一组相关操作当成一个整体来执行，要么全部成功，要么全部失败。它主要是为了解决数据一致性问题。

### 面试官追问

那你怎么理解 `COMMIT` 和 `ROLLBACK`？

### 候选人示范回答

`COMMIT` 表示事务里的修改正式提交生效，`ROLLBACK` 表示把事务中的修改撤销掉，回到事务开始前的状态。简单理解就是一个确认保存，一个撤销本次改动。

### 回答提醒

- 核心词是“一致性”
- 别把回答绕太复杂

## 第 7 组：子查询和 JOIN 怎么区分？

### 面试官

你觉得子查询和 JOIN 有什么区别？

### 候选人示范回答

我的理解是，`JOIN` 更像把多张表直接关联起来取结果，而子查询更像先得到一个中间结果，再交给外层查询继续使用。很多题两种写法都能实现，但思路不太一样。

### 面试官追问

那什么时候你会优先想到子查询？

### 候选人示范回答

当题目本身就像“先求一个结果，再根据这个结果继续筛选”时，我会更容易先想到子查询。比如先求平均分，再筛选高于平均分的记录。

### 回答提醒

- 不要硬说谁一定更好
- 重点说“思路区别”

## 第 8 组：视图在你理解里是干什么的？

### 面试官

你怎么理解视图？

### 候选人示范回答

我理解视图主要是把一段常用的复杂查询逻辑封装起来，后面就可以像查表一样继续使用。它比较适合封装多表联查或者重复使用的查询逻辑。

### 面试官追问

那视图和表的区别是什么？

### 候选人示范回答

表更偏向真实数据存储，视图更偏向查询逻辑封装。也就是说，真正的数据还是在底层表里，视图更多是提供一个更好用的查询入口。

### 回答提醒

- 关键词是“封装查询逻辑”
- 别把视图说成“另一张真实表”

## 第 9 组：EXPLAIN 和查询优化你现在掌握到什么程度？

### 面试官

你现在对 `EXPLAIN` 和查询优化了解多少？

### 候选人示范回答

我目前的理解还在入门阶段，主要知道 `EXPLAIN` 是用来看 SQL 执行计划的工具，可以辅助判断是否可能使用了索引、扫描行数是否偏大、查询是否有优化空间。

### 面试官追问

那你觉得优化的核心目标是什么？

### 候选人示范回答

我觉得核心目标是让数据库用更低的成本拿到正确结果，比如减少无效扫描、减少不必要的数据读取、提高索引利用率，而不是单纯把 SQL 写得更复杂。

### 回答提醒

- 可以诚实说自己是入门阶段
- 但要把已掌握的关键点说清楚

## 第 10 组：如果让你总结一下自己的 MySQL 学习情况，你会怎么说？

### 面试官

你现在觉得自己对 MySQL 掌握到什么程度？

### 候选人示范回答

我现在对 MySQL 的基础操作比较熟，包括建库建表、增删改查、多表查询、基础事务、子查询、视图、索引和 `EXPLAIN` 入门，也能用 Python 连接 MySQL 做基础操作。对更深入的优化和底层原理，我还在继续学习。

### 面试官追问

那你觉得你目前最重要的收获是什么？

### 候选人示范回答

我觉得最重要的收获不是只会写 SQL，而是开始有一些正确的方法意识了。比如修改前先确认范围、多表查询先拆关系、写查询时考虑是否需要索引和是否有优化空间。

### 回答提醒

- 回答掌握范围时要诚实
- 回答收获时强调方法意识
