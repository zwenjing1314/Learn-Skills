## 1. 为什么说主键和唯一约束不完全一样？

### 参考答案

两者都能保证字段值不重复，但主键更强调“唯一标识一条记录”，而且一张表通常只有一个主键；唯一约束可以有多个，更适合业务上需要防重复但又不是主标识的字段。

### 追问点

- 主键通常只有一个
- 唯一约束可以有多个
- 主键更偏“核心标识”

## 2. 为什么更新和删除前，很多人都会先写一条 SELECT？

### 参考答案

因为 `UPDATE` 和 `DELETE` 是修改型操作，风险高。先写 `SELECT` 可以确认条件到底会命中哪些数据，避免误改、误删整张表。

### 追问点

- 先确认命中范围
- 是一种安全习惯
- 尤其适合生产环境思维

## 3. 为什么说外键能保证数据一致性？

### 参考答案

因为外键限制了子表中的关联值必须在主表中真实存在。例如成绩表里的学生 ID 必须能在学生表里找到，这样可以避免出现“成绩存在，但学生不存在”的脏数据。

### 追问点

- 保证关联值真实存在
- 避免脏数据
- 体现表之间的关系约束

## 4. 为什么多表设计比把所有字段塞进一张大表更合理？

### 参考答案

因为多表设计可以减少冗余、降低重复数据、让结构更清晰，也更符合真实业务关系。虽然查询时会复杂一些，但从维护性和扩展性看更合理。

### 追问点

- 减少冗余
- 结构更清晰
- 更利于维护和扩展

## 5. 为什么索引能提升查询速度？

### 参考答案

因为索引让数据库在查找数据时不必总是从头扫到尾，而是可以更快定位到目标范围。它本质上是在“帮数据库更高效地找数据”。

### 追问点

- 减少无效扫描
- 更快定位数据
- 核心目标是提升查询效率

## 6. 为什么索引有时建了也不一定明显生效？

### 参考答案

常见原因有两个：一是数据量太小，全表扫描成本本来就不高；二是 SQL 写法可能不利于索引使用，比如对字段做函数处理，或者条件不够合适。

### 追问点

- 数据量小差异不明显
- SQL 写法可能影响索引利用

## 7. 为什么 `SELECT *` 在面试里经常会被追问？

### 参考答案

因为它看起来简单，但会暴露你是否有性能和工程意识。如果只需要两列却查所有列，可能带来额外的 I/O、网络传输和程序处理成本。

### 追问点

- 不一定是错，但常常不够好
- 要有“按需取字段”的意识

## 8. 为什么 `GROUP BY` 常和聚合函数一起出现？

### 参考答案

因为 `GROUP BY` 的作用是把数据先按某个字段分组，而聚合函数如 `COUNT`、`AVG`、`SUM` 则是在每组内部做统计。两者通常是配套出现的。

### 追问点

- 先分组
- 再统计
- 常见搭配是 `COUNT`、`AVG`、`SUM`

## 9. 子查询和 JOIN 在面试里怎么区分着回答更稳？

### 参考答案

可以简单回答：`JOIN` 更像把多张表拼接起来取结果，子查询更像先得到一个中间结果，再让外层查询继续使用。很多题两种写法都能做出来，但思路不同。

### 追问点

- `JOIN` 偏联表组合
- 子查询偏中间结果
- 两者都常用，不是非此即彼

## 10. 为什么事务能保证一致性？

### 参考答案

因为事务把一组相关操作当成一个整体来处理，只有全部成功才提交。只要中间任何一步失败，就可以回滚，避免只执行了一半导致数据状态不完整。

### 追问点

- 一组操作作为整体
- 失败可回滚
- 防止执行一半的数据异常

## 11. 为什么视图适合封装复杂查询？

### 参考答案

因为有些查询会频繁使用，而且 SQL 很长，比如多表联查、统计报表。做成视图后，后续就可以像查表一样继续使用，降低重复编写成本。

### 追问点

- 封装重复查询
- 简化使用入口
- 提高可读性

## 12. 为什么说视图不是拿来替代表的？

### 参考答案

因为视图本质上更多是查询逻辑封装，而不是底层真实数据存储。真正的数据仍然在原表里，视图依赖原表而存在。

### 追问点

- 视图偏逻辑层
- 原表才是真实数据存储层

## 13. 为什么 `NULL` 和空字符串不能混为一谈？

### 参考答案

因为 `NULL` 表示未知或缺失，而空字符串是一个实际存在的值，只不过内容为空。两者语义不同，处理方式也不同。

### 追问点

- `NULL` 是未知/缺失
- 空字符串是实际值
- 语义不同

## 14. 为什么判断 `NULL` 要用 `IS NULL`？

### 参考答案

因为 `NULL` 不是普通值，而是“未知”的状态。在 SQL 中，不能用 `= NULL` 来判断它，必须用 `IS NULL` 或 `IS NOT NULL`。

### 追问点

- `NULL` 不是普通值
- 要用 `IS NULL`

## 15. 为什么分页查询通常不用一次把所有数据都查出来？

### 参考答案

因为实际业务里数据量可能很大，一次性全查出来会占用更多内存、网络和数据库资源。分页查询能把读取压力拆开，更适合页面展示和接口返回。

### 追问点

- 控制返回量
- 降低资源压力
- 更适合实际业务场景

## 16. 为什么说 `EXPLAIN` 不是优化本身，而是分析工具？

### 参考答案

因为 `EXPLAIN` 不会自动帮你把 SQL 变快，它只是把数据库计划如何执行这条 SQL 展示出来，让你有依据去判断是否需要调整索引或改写 SQL。

### 追问点

- `EXPLAIN` 是观察工具
- 真正优化还得靠你改 SQL 或改索引

## 17. 为什么查询优化不等于“把 SQL 写复杂”？

### 参考答案

优化的核心目标是让数据库更高效地拿到结果，而不是让 SQL 看起来更厉害。很多时候更好的优化反而是写法更清晰、过滤更明确、字段更精简。

### 追问点

- 核心是效率，不是炫技
- 简洁合理通常比复杂更重要

## 18. 为什么经常说要给 WHERE、JOIN、ORDER BY 涉及的字段优先考虑索引？

### 参考答案

因为这些字段最常参与数据定位、结果排序和表间关联，是数据库执行查询时负担最重的环节之一。在这些位置建立合理索引，收益通常最直接。

### 追问点

- 过滤字段
- 排序字段
- 联表字段

## 19. 如果面试官问“你学习 MySQL 到现在最重要的体会是什么”，怎么答更好？

### 参考答案

可以回答：我觉得最重要的是先把基础链路打通，不只是会写 SQL，还要知道为什么这样写、风险在哪、结果会是什么。比如更新删除前先确认范围、多表查询先拆关系、索引和 `EXPLAIN` 要先建立基本意识。

### 追问点

- 不只是会写
- 还要会解释、会判断风险
- 强调方法论

## 20. 如果面试官问“你现在最熟的 MySQL 内容有哪些”，怎么答更自然？

### 参考答案

可以回答：我目前比较熟的是建库建表、增删改查、多表查询、基础事务、子查询、视图和索引入门，也能用 Python 连接 MySQL 做基础操作。对于更深入的性能优化和底层原理，我还在继续学习。

### 追问点

- 先说自己掌握的范围
- 再诚实说明还在进阶的部分
- 表达要稳，不要硬装全会
